Where your app runs

Five words that get used loosely, pinned to the machines in your own project — plus the one idea the rest hangs off.

A server is a running program. Not a place, not a language, not a machine. server.js is a recipe sitting on a disk; the server is what exists once something runs it. Stop the program and the server stops existing, even though the file is untouched. That is why Ctrl-C broke the page.

The five words

Colour marks the role, and it's used consistently in every diagram below.

Storing
Keeping code or data somewhere safe. Nothing is running. GitHub holds your code · Postgres holds your reminders
Hosting
Someone provides an always-on machine so your thing stays available to other people. GitHub Pages hosts files · Render or Fly would host a program
Serving
The act of handing something over when asked. Hosting is the arrangement; serving is what happens each time. what GitHub Pages does on every page load
Client
The thing that asks. It runs the app, but only for the person sitting in front of it. Chrome, running index.html + style.css + app.js
Server
A running program that waits for requests and answers them. GitHub Pages · the CDN · Supabase · your tiny one

Same language, two different homes

Both files are JavaScript. Neither would survive in the other's place.

app.js

run by Chrome, on every visitor's machine

  • Can draw on screen
  • Cannot read files off the disk
  • Cannot listen on a port
  • Anyone can read and edit it
  • Runs top to bottom, then finishes

server.js

run by Node, on one machine you control

  • Has no screen to draw on
  • Can read and write files
  • Can listen on a port
  • Nobody else can see or change it
  • Reaches listen() and stays running

That last pair is the whole reason password checks live on a server. A rule enforced in app.js is a rule running on the machine of the person you're enforcing it against.
